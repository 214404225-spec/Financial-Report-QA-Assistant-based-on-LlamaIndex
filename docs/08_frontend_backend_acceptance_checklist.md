# 前后端功能连接验收清单

本文档用于**逐项确认** Gradio 工作台中每个用户操作是否正确触发后端逻辑并得到预期界面反馈。架构与接口索引见 **[07_frontend_backend_api.md](07_frontend_backend_api.md)**；溯源数据契约见 **[01_architecture_data_flow.md](01_architecture_data_flow.md)**。

**使用方法**：在「实测」列打勾或填日期/姓名；异常时在「备注」记录终端首行报错、Network 状态码或截图编号。若希望**由 AI 按模块逐步帮你核对**，请使用本文 **§7**。

## 7. 使用 AI 协助逐项检查（推荐流程）

本节说明如何把 **§0–§4** 交给 AI（如 Cursor / ChatGPT）**按模块逐步核对**：由你提供运行证据，由 AI 对照本清单与 **[07_frontend_backend_api.md](07_frontend_backend_api.md)** 判断是否「前后端已正确连接」。

### 7.1 你需要准备什么（每次对话尽量附上）

| 材料 | 用途 |
|------|------|
| 本文件对应章节（§0 / §1 的 **A–C** / §2 的 **D–G** / §3 / §4） | 明确验收 ID 与预期 |
| 终端中运行 `python src/ui/app.py` 的输出或报错全文 | 判断启动与后端异常 |
| 浏览器 **F12 → Network**：相关请求的 URL、状态码、失败响应体（可文字摘录） | 判断 Gradio 与 `/file=...` 是否通 |
| 界面截图或步骤文字（「我点了什么 → 界面变成什么」） | 判断 UI 反馈是否符合预期 |
| 若核对代码：说明当前分支，并让 AI 读取仓库中的 `src/ui/app.py` 与 **[07](07_frontend_backend_api.md) §5** | 核对事件绑定是否与文档一致 |

**限制**：AI 不能直接操作你的浏览器；**「通过 / 未通过」必须基于你提供的证据**。若信息不足，应要求 AI 明确列出「还缺哪一条材料」。

### 7.2 推荐顺序（一次只查一个 ID）

按 **§0 → A → B → C → D → E → F → G → §3 → §4** 顺序开新对话或同线程续问，避免混淆。每步结束后在本清单「实测」列打勾或记备注。

### 7.3 可复制：交给 AI 的提示模板（按模块替换 `{...}`）

**通用开头（每条消息可重复贴）**

```text

当前验收项：{填写 ID，如 §0 或 A}。
请你对照 docs/07_frontend_backend_api.md 里 §5 的接口与事件绑定，判断以下证据是否满足该验收项的「预期结果」。

【环境】OS：{...}，Python/venv：{...}
【终端输出摘录】
...
【Network 摘录】（如有）
...
【界面现象】（截图已附 / 文字描述）
...
【我的判断】不确定 / 认为失败，因为：...

请输出：
1) 结论：通过 / 未通过 / 证据不足无法判断
2) 依据：逐条对照验收清单中的预期

```


**专项：§4 gradio_client**

```text

...
请对照 08 清单 §4，说明是否覆盖 §1–§2 中的操作；若调用失败，可能原因是什么。
```

### 7.4 要求 AI 给出的输出格式（便于你填表）

建议强制 AI 使用固定小节，便于粘贴进 **§5 结果汇总** 或备注：

1. **验收 ID**：如 `B`  
2. **结论**：通过 / 未通过 / 无法判断  
3. **对照预期**：引用清单中该 ID 的「预期结果」逐条打勾或说明不符点  
4. **根因假设**（若失败）：一条主因 + 一条备选  
5. **下一步**：你（人）要执行的一条具体命令或一次 UI 操作  

### 7.5 AI 检查后的自检

- AI 若引用行号，你在本地打开 `src/ui/app.py` **核对当前文件是否已变更**。  
- 「代码说已绑定但 UI 无反应」时，优先补 **§3** 的 Network / Console 证据再追问 AI，避免纯猜。
